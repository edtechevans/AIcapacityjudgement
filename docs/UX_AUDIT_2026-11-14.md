# Student Experience Audit — 14 November 2026
**Scope:** AI Capacity × Judgement Learning Studio · Grades 6–10 · Full source-level UX pass  
**Release:** v14  
**Status:** Implemented and automated regression-tested. Visual validation with an actual browser and moderated student testing remain outstanding.

## Review principle

A strong learning interface makes the next meaningful action obvious, teaches before testing, gives students choices they understand, and accurately describes learning evidence. It does not mistake high completion or a polished hero for educational quality.

The current release preserves the Capacity and Judgement brand, two complementary curricula and the five-stage learning sequence.

## Page-by-page findings and implemented changes

| Page or experience | Finding | Implemented improvement |
| --- | --- | --- |
| **Home / hero** | “Start here” arrow suggested a button but the journey card was inert. | Made the entire card a native, focusable lesson link with clear accessible name, hover, focus and keyboard activation. The selected target follows the same start/resume/revisit logic as the main call to action. |
| **Home / headline** | Supporting copy was generic compared with the memorable title. | Updated to “Learn what AI can do, when it helps, and how to use it thoughtfully in real situations.” |
| **Home / grade switching** | Selecting another grade on the dashboard unexpectedly opened the course listing. | Changing grade now refreshes the dashboard in place, with the correct grade-specific journey and progress. |
| **Courses** | Featured learning sometimes said “start” when the student was already progressing; counts were hard-coded. | Introduced contextual resume language, curriculum-derived pathway counts and clearer wording for an optional check-in. |
| **My learning** | Without a check-in, the page was largely empty even when a learner had completed modules. | Always show separate Capacity and Judgement practice progress, actionable pathway cards and next-module suggestions. The six-question check-in is optional and enriches the page rather than gating it. |
| **Check-in** | Progress lacked explicit accessible progress semantics and focus jumped to the top between questions. | Added named progress information and focus on the newly displayed question. Results remain formative, not ability placements. |
| **Learning snapshot** | A 3-item score could feel like a grade; old quadrant labels could imply fixed learner types. | Clarified the evidence as only three choices per pathway and replaced labels with growth-oriented learning moves. |
| **Lessons** | The progress display said 20% complete before the first teaching stage was completed. Stage changes repeatedly focused the page title rather than the new learning. | Show completed stages accurately and move keyboard focus to the active stage heading, modelled example or feedback where appropriate. |
| **Authentic application** | Choosing a context or response format caused a full re-render that could lose keyboard position. | Return focus to the selected control after re-render; preserve the three manageable Choose → Plan → Create & Review stages. |
| **The idea / About** | The page was abstract and diagram-first, making it difficult to see how courses actually work. | Put the two learning pathways and five-stage teaching sequence first, then use the quadrant as a reflective framework rather than a student label. |
| **My profile** | Clearing saved work happened on a single click without warning. Import UI showed both a label and an extra native file button. | Added an explicit cancel/confirm step before deleting local records and simplified the backup chooser. |
| **Site-wide feedback** | Some important messages were only announced to screen readers and not visually displayed. | Added a visible, screen-reader-announced status toast for copy, save and error feedback. |
| **Responsive UI** | Small screens needed a clearer reading rhythm for the expanded pages and controls. | Added scoped responsive rules for cards, pathway indicators, confirmation controls and My Learning. |

## Validation

The automated test suite covers:
- Complete instruction-first journeys for **all 30** modules, including applied work and reflection.
- Initial grade selection, homepage learning link and contextual action wording.
- Filtered course routes, grade changes and unfinished lesson resume.
- Check-in completion, snapshot feedback and returning to a new attempt.
- An informative My Learning page without the optional check-in.
- Five-stage progress semantics and browser checkpoint retention.
- Confirm/cancel protection before clearing local learning records.
- Progress import validation and legacy record migration.
- Asset presence, icon dimensions and brand colour contrast pairings.

The GitHub Actions **Learning Studio quality** workflow runs these tests on relevant code changes. These tests are **not** a substitute for visual inspection or real student feedback.

## Remaining risks and future work

1. **Rendered visual QA:** Browser inspection was unavailable in this session. Validate desktop and mobile layouts, including 320px width, 200% zoom, safari/mobile navigation and screen-reader interactions before claiming full accessibility compliance.
2. **Student usability:** Observe real learners in Grades 6, 8 and 10 explaining the learning, finishing an authentic challenge and finding their next module without prompting.
3. **Learning evidence:** Site completion represents checked participation and a self-confirmed plan. Written work is not teacher-assessed, uploaded or centrally saved.
4. **School readiness:** Real authentication, secure portfolio submissions, educator feedback and data governance require a separate architecture and privacy review.

## Non-negotiable product standard

**Meaningful learning before measurement.** Every module continues to follow Learn → Model → Practise → Apply → Reflect. A student who chooses not to use AI for a defensible learning reason is not treated as less capable or less successful.
